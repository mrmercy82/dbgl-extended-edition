DBGL Extended Edition - Changes since 0.100 beta 17
===================================================

Based on DBGL 0.100 beta 17 by Ronald Blankendaal (https://dbgl.org), source code.


0.101 alpha 53 (in progress)
----------------------------
New
- Windows 3.x: for profiles that start Windows (WIN.COM), "Check..." now
  looks into its SYSTEM.INI and WIN.INI (reading only):
  - what Windows starts then: the program after WIN, "run=" and "load=" of
    WIN.INI, "shell=" of SYSTEM.INI (if not the Program Manager); if such a
    program is not on the drives of the profile, there is a warning,
  - whether the sound driver (Sound Blaster: port, interrupt, DMA) fits the
    settings of DOSBox, else Windows stays silent,
  - whether an S3 display driver has the S3 card of DOSBox, else Windows
    does not start or shows nothing.
  Also the groups of the Program Manager (PROGMAN.INI and the .GRP files):
  a note on the programs outside the folder of Windows in them, and one on
  the program items that point to a missing program (programs on a CD image
  count as there); the startup group counts to what Windows starts.
  Windows is also recognized when own lines of the autoexec start it ("C:",
  "cd \WINDOWS", "win"), not only as the start program WIN.COM.
  New in the context menu of the profiles under "Tools": "Programs of
  Windows 3.x as profiles..." shows the programs of these groups; each one ticked gets a
  profile of its own, a copy of the Windows profile whose Windows starts the
  program right away ("win C:\BADMOJO\BADMOJO.EXE"), with the name of the
  program item as title.
  The solution each time: take the value of Windows into the profile.
  Programs for Windows 3.x as setup or further program no longer count as
  faults in such profiles; a setup program can be started through WIN.COM.
- Windows 95/98: for profiles that boot Windows from a hard disk image
  ("imgmount 2 ... -t hdd", "boot -l C"), "Check..." reads the image
  (reading only, FAT): notes on the programs in the Start menu (shortcuts,
  without those of Windows itself), on those Windows starts on its own
  (startup folder, "run="/"load=" of WIN.INI) and on the shortcuts that point
  to a missing program on C:. Profiles of their own per program are not
  offered here: DBGL would have to change the image for that.
- Settings, DOSBox: four notes can be hidden, and they are hidden from the
  start: missing program items in Windows profiles, the programs in the
  Program Manager or Start menu, the programs Windows starts by itself (a
  missing one is still reported) and repeatedly short sessions. They are
  then left out of "Check" and the profile list.
- One import from a folder instead of two: Profiles > Import > "Import
  games from folder..." finds the known games by their files (database of
  DBGL and learned from profiles, with a DBConf configuration as before) and
  also every other game folder with a DOS program that no profile uses (as
  "Import games without profile from folder" did), with the start program
  guessed; the folder of the game is then drive C:. The title of such folders
  is looked for in their text files (FILE_ID.DIZ, README, READ.ME, *.TXT,
  *.NFO: lines like "Welcome to ...", "... Version 1.2", "... (c) 1992", a
  title line in capitals) and in the label of their CD images; a title is
  only taken if the MobyGames database that comes with DBGL has exactly one
  game of that name, with its details (score 10). Otherwise the folder name
  stays (score 0). Everything is only read.
- Menu Profiles: all imports are in the submenu "Import": the import from a
  folder, then GOG/Steam, eXoDOS, LaunchBox, ScummVM, D-Fend Reloaded and
  DFendX, then the files of DBGL. The welcome wizard also has only one button
  for the import from a folder.
- Import from a folder, learned games: after the search DBGL tells how many
  of the games learned from profiles were recognized, for which the start
  program is there but has another checksum (changed by the game or another
  version), and which were not found by the name of their start program. A
  learned game whose start program changed is recognized if its setup
  program stayed the same (score 30).
- Import from a folder, further rules: SMARTDRV.EXE, HIMEM, EMM386, MSCDEX
  and other DOS tools do not count as start program. If the game folder has
  a Windows in it (WIN.COM with SYSTEM.INI), the profile starts WIN.COM: if
  Windows starts the game itself ("run=", "load=", shell), that is all, else
  WIN.COM gets the one program of the program groups outside the folder of
  Windows. The same start program, or one of the same name, in a folder and
  a folder below it makes one game, the upper one, with a note on the other.
  The search for further game folders shows which folder it is looking at;
  a fault there is reported, the games recognized stay. Long lines in text
  files are skipped for the title (they could hold the search up for
  minutes), the same search term is asked only once. The DBConf button is
  called "Take the DOSBox configuration from DBConf" and has a tooltip. The
  log at the end begins with that of the search (with the report on the
  learned games), so that it is saved with it. A game recognized in the
  chosen folder itself (loose files there) gets a note and is not ticked:
  its profile would have the whole folder as its drive. If the same title is
  found in several folders (copies, an installer folder next to the game),
  each gets "same title also in ..."; only one stays ticked: the one with the
  highest score, then the one in a folder with this game alone (not the
  folder of a collection that brings its program along), then the one whose
  folder name begins like the title ("PRINCE" for Prince of Persia), then the
  shortest path. If all learned games were recognized, the log says so too.
  In the log, profile IDs from 1000 on have no thousands separator
  ("ID:1000", not "ID:1,000"). These notes are in a column "Notes" of the list to tick (for
  folders not recognized also where the title comes from). Several learned
  games in one folder (such as Wing Commander II with Special Operations 1
  and 2) are each recognized; before, the folder got only one of them.
- "Manage learned games..." (menu Profiles and context menu under Tools):
  all games learned from profiles, with a search. Change the details, choose
  the start or setup program anew (name and checksum are taken from the file
  chosen, the path is not kept) or forget entries; each change is saved at
  once.
- Import and export wizards: the log at the end can be copied (selection or
  all) and saved as a text file, as in the window of DOSBox.
- "Complete profiles..." (menu Profiles and context menu under Tools, for the
  selected profiles): first the title, then the details, then the covers,
  because details and covers are searched by the title. Each profile is
  looked up in the MobyGames database that comes with DBGL, else in the text
  files of its game folder, and gets a traffic light: green found (or details
  there), yellow a proposal to check, red nothing found. Titles can be
  changed by double-clicking and are looked up again at once. "Apply" fills
  in title and details for the ticked profiles (developer, publisher, year,
  genre, description only where the profile has none; can be undone like
  other changes of many profiles); then, if wished, "Fetch covers" for these
  profiles. The welcome wizard has a page of its own for it, "Check the
  titles", between the import and the game information; the page of the game
  information says what of it is done already. A profile that has a cover
  already is not "nothing found" but "cover there". Boxes, state and title
  have tooltips; applying shows a progress bar.
- Fetch covers for profiles without pictures: TheGamesDB is the source at
  first (then the one chosen here the last time). A note says that the
  databases answer only so many questions at a time (IGDB the fewest) and to
  do it again with many profiles; profiles that have a cover by then are left
  out. Boxes and findings have tooltips, saving shows a progress bar. Whether
  a profile has a picture already DBGL now checks in the folder itself:
  profiles with a cover saved since came into the list again otherwise, grey
  with "not found".
- Presets (context menu of the profiles and profile dialog): each group has
  a heading ("System and speed", "Picture (DOSBox Staging ...)", "Own
  presets"). "Picture" names the newest DOSBox Staging set up in DBGL that
  has them (else 0.83); the entries themselves no longer name the version.
- Context menu of the DOSBox versions: "Remove with folder..." is now
  "Remove DOSBox version with folder...".
- Developers, publishers and genres: names from MobyGames with a no-break
  space ("Accolade, Inc." with U+00A0) made a second entry next to the same
  name with a normal space. DBGL now stores such spaces as normal ones and
  takes the entry already there, also with other case ("Role-playing
  (RPG)"). "Database cleanup" merges entries of the same name already
  there and tells how many. In a collection of 180 profiles there were 28
  such duplicates.
  After that, "Database cleanup" shows similar, but not equal entries to
  tick ("Sierra On-Line" / "Sierra Online", "Dynamix, Inc." / "Dynamix",
  "Strategy" / "Strategy/Tactics"): for each group ticked one chooses the
  name that stays; nothing is chosen at first.
- Check: what DOSBox wrote at the last start of a profile is read along and
  shown as a note: DOSBox-X finds no WinPcap for the network card (solution:
  [ne2000] backend = slirp), DOSBox may not create a folder, DOSBox does not
  take a value, DOSBox finds no ROMs of the MT-32 (with the folders DOSBox
  Staging looked in). Only messages whose wording is known from real output
  are recognized; the message of DOSBox-X about a folder when started with
  -savedir (which DBGL makes itself) does not count. If a value not taken is
  only in the configuration file of the DOSBox version (such as "enable
  supermegazeux tweakmode" empty in dosbox-x.conf), the note names that file.
- Profile list: warning and note signs with their tooltip are found again at
  once when something changed without the list being built anew (DOSBox
  ended, profile repaired, settings changed); before, they sometimes showed
  the new state only after DBGL was started again.
- Check: a hard disk image that cannot be written to (write protected or
  without permission) is reported: Windows 95 in it reports write errors
  otherwise, and ScanDisk runs at every start.
- Check: "Export for the developer..." puts the results with the
  configuration files of the profiles into a text file to send to the
  developer. Folders, user name, computer name and e-mail addresses are
  replaced; notes, links and own fields are left out. The whole text is
  shown before saving.
- Check: "eXoDOS for comparison...": with an eXoDOS collection on the
  computer (also the one imported from), "Check" tells for profiles with
  exactly the title of one of its games which settings about the game eXoDOS
  sets otherwise (memory, machine, sound card ...). The values can be taken
  over, but only chosen by hand. For DOSBox versions other than 0.74 the
  speed (core, cycles) is left out, DOSBox Staging gets the values under its
  names. The files of eXoDOS are only read.
- Database cleanup: a window first tells what happens and what stays as it
  is, and makes a backup if wanted (on at first: database, profiles,
  templates, settings), which shows in "Manage backups" and can be restored
  there. The cleanup is now also offered in the statistics window. The old
  German message wrongly spoke of deleted "profiles"; only unused entries
  of the lists are deleted.
- Statistics, new sections: play time of the last 12 weeks, by weekday and
  by time of day; days played with the longest and the current streak and
  (on the web page) a calendar of the last 12 months; the length of the
  play sessions; games never started by the age of their profile and the
  oldest of them; game series and publishers with play time; the state of
  the collection (without pictures, year, genre, developer, publisher, with
  warnings, each with its share); the largest games by disk space.
- Statistics: "Year in review" as a web page for this year and earlier
  years with play time (play time, sessions, games and new games, days
  played and streak, longest session, first and last game, strongest month,
  favourite genre, most played games, play time per month, calendar).
  "Random unplayed game..." suggests a game never started and selects it in
  the list.
- Check: a note when the last (at least three) play sessions of a profile
  in a row were shorter than 3 minutes; older, longer ones do not count: the
  game may not start right (any more) or end by itself.
- Restore an earlier profile: with each earlier state DBGL now also keeps
  the DOSBox version the profile had then. Restoring gives the profile that
  version back if it is still there (else the current one stays, with a
  note); the list shows it next to the date when it was another one. For
  states from before alpha 53 the version is not known.
- DOSBox Staging also reads its own configuration in the user folder before
  the files of DBGL (on Windows %LOCALAPPDATA%\DOSBox\dosbox-staging.conf):
  what DBGL does not set comes from there, and its [autoexec] runs too.
  "Check" tells for the DOSBox version what of it counts (settings the
  configuration of the version does not set and that differ from the
  default, and autoexec lines). New in the settings (DOSBox): "Start DOSBox
  Staging without the configuration in the user folder" (-noprimaryconf).
  DOSBox-X with -conf reads only the files it is given.
- Edit profile, Audio: the button next to "Mixer command" now reads "Set
  volumes..." instead of "...".
- Welcome wizard at the first start (when there are no profiles yet):
  language and appearance; DOSBox (the advice to download both DOSBox
  Staging and DOSBox-X, two sentences each on Staging, DOSBox-X and 0.74-3;
  finding or downloading); taking over the first games (from a folder, known
  games recognized by their files, GOG/Steam, LaunchBox, eXoDOS, ScummVM,
  D-Fend Reloaded); game information (recommended: the Metropolis Launcher
  MobyGames Database that comes with DBGL) and covers (recommended:
  TheGamesDB.net) on a page each, with how it is done and that a precise
  profile title makes the search better; at the end, what comes next. It
  enters the DOSBox 0.74-3 that comes with DBGL when it is missing; else it
  only calls what DBGL has anyway, every step can be skipped. Who has
  profiles already (e.g. after an update) does not get it by itself; Help >
  "Welcome wizard..." opens it at any time.
- Own recognition of known games: Profiles > "Learn selected profiles for
  the recognition" keeps the start and setup program (name and checksum) of
  the selected profiles with title, developer, publisher, year and genre
  (also in the context menu under Tools). A profile with a title and at
  least developer, publisher or year is also learned when it is saved in the
  profile dialog. "Import known games in folder" then recognizes these games
  before the database that comes with DBGL (which has checksums for only
  part of its games), e.g. on another PC or after a new installation. Kept
  in config\known-games.json, without paths; the database that comes with
  DBGL stays as it is.
- "Import games without a profile from folder" recognizes known games: a
  game folder learned from a profile or in the database that comes with DBGL
  (looked at with its folders below) gets title, developer, publisher, year,
  genre, description, start and setup program from there (source "Folder,
  known game"); the other folders are in the list with their folder name as
  before. So all game folders can be taken over at once, the known ones
  already filled in.

Changed
- DBConf (DOSBox configurations collected from other DBGL users) now comes
  from a database that comes with DBGL (db/dbconf.*) instead of
  share.dbgl.org; DBGL no longer asks the internet for it. Taken over from
  DBGL 0.100 beta 18 by Ronald Blankendaal, who made the database and
  allowed the Extended Edition to ship it. The EE uses it wherever there was
  DBConf: the profile dialog, the "Add Game" wizard and "Import known games
  from folder". The import takes a configuration only for exactly the same
  title (before, "Doom" got none because "Doom II" was found too). Entries
  without own settings now say so instead of showing an empty field. Sharing
  an own configuration is gone (share.dbgl.org will soon take none any
  more). Without the database the DBConf buttons do not show.
- "Check..." names the configuration of DBConf for profiles of DOSBox 0.74
  when there is one for exactly this title and it sets something otherwise
  than the profile ("Note: DBConf has a configuration ... with [dosbox]
  machine = cga; the profile has ..."). It can be taken over as a solution,
  but it is not chosen at first, nor by "Choose all solvable": the
  configurations were sent in by users. For DOSBox Staging and DOSBox-X
  there is no note, as all configurations of DBConf were made for 0.74.
  Only settings about the game are compared (machine, memory, CPU,
  EMS/XMS/UMB, sound cards, joystick), not those about the own computer
  (window, output, keyboard layout, MIDI device). For entries without own
  settings the full configuration of DBConf counts: a Doom profile with
  memsize = 8 gets the note about memsize = 16.
- Loading DBConf (profile dialog, "Add Game" wizard, import of known games):
  for profiles of DOSBox 0.74 DBGL now takes over, besides the own settings
  of the entry, the settings about the game from its full configuration
  (machine, memory, CPU, EMS/XMS/UMB, sound cards, joystick). A Doom profile
  with memsize = 8 so gets 16 again; window, output, keyboard and MIDI
  device stay. For other DOSBox versions it stays with the own settings,
  values that DOSBox Staging calls otherwise under their new name. The
  dialog shows what is taken over, and for versions other than 0.74 says
  why it is less.
- Download DOSBox: for DOSBox-X each build now shows its kind ("Visual
  Studio" or "MinGW") in front, with a sentence below on what it is good for
  (Visual Studio is what the DOSBox-X project recommends for Windows; MinGW
  calculates with floating-point numbers more exactly and supports
  networking over "slirp"). The MinGW builds are now called
  "dosbox-x-mingw64-...-portable.zip" (no "win" in the name) and so were not
  offered, only Visual Studio twice (64 and 32 bits); now they come right
  after the recommended build, the variants for old computers ("lowend")
  last. New is a field "Folder name": filled in by build
  ("dosbox-x-2026.08.31-mingw" for MinGW), so that two builds of a version do
  not end up in one folder; if the folder is there with files already, DBGL
  proposes a free name ("...-2") and says so. The name can be changed.
- A new installation opens the main window maximized.
- Importing games (folder, GOG/Steam, LaunchBox, eXoDOS, ScummVM): the
  newest DOSBox Staging entered is chosen as DOSBox version at first (before:
  the default version); games that need DOSBox-X still get DOSBox-X. Without
  Staging it stays the default version.
- Import from a folder: folders of DOSBox and ScummVM themselves (the DOSBox
  versions entered in DBGL, and folders with dosbox.exe, dosbox-x.exe or
  scummvm.exe right in them) are no longer offered as games.
- The buttons "All" and "None" of the imports are now above the list (below
  it they could be cut off in a low window); "Get covers for profiles
  without images" has them as well.
- Editing several profiles at once with an online lookup: a title written
  only a little differently (punctuation, case, accents, "&"/"and", a
  leading "The") now counts as an exact match when it is the only one. For
  MobyGames and TheGamesDB, new settings also save one cover per profile
  there (before: none).
- "Import known games in folder": when a recognized game has no start
  program, it is guessed (the start program of the database by its name,
  also when changed; else one named like the folder; else the only program
  in the folder that is no setup, installer or DOS extender). The game folder
  can be opened from the list (context menu, or a double click on the
  folder). When games have no start program, one message names them,
  instead of the same line per game.

Fixed
- Duplicate: own lines of the autoexec DBGL leaves as they are (e.g. "SET
  TEMP=..." or "win" after "cd \WINDOWS") were missing in the copy.
- The import and the "Add Game" wizard no longer fill in a setup program for
  Windows by themselves (for Ultima VII Part Two the database of DBGL named a
  SETUP.EXE that sets up a screen saver of Windows 3.x). "Check..." offers
  the solution "remove the setup program from the profile" for such a setup
  program.
- On Windows the firewall asked after the start whether Java may use the
  network: DBGL opened its port for "Send to" and the start from Steam
  (4740) to the whole network, so that other computers could add profiles
  or start games there. It now only takes connections from this computer;
  the firewall does not ask any more.
- Help > "New features" did not show the parts about alpha 51 and 52 since
  alpha 51 (the files whats-new-de/en.txt shipped next to it had them).
- "Import known games in folder" gave folders wrong games: a folder with
  known files but no program (e.g. a folder of game data) left its matches
  behind, and the next folder then got that game. Also, files that several
  games have alike counted (e.g. SIERRA.COM of the games of Sierra, the
  SETUP.EXE of the games with the Build engine), and the setup program or
  one further file alone was enough. Now only files that belong to exactly
  one game count, and without the start program it takes the setup program
  and one further file, or three further files. The search also shows how
  many games are learned from profiles and where the file is.
- "Import known games in folder": a start or setup program in a folder
  below the game, chosen in the list, was entered as a file of that name in
  the game folder itself, which was not there. The list now shows the
  programs with their folder.
- Saving now also cuts paths and parameters (setup, alternative programs,
  captures folder, configuration file, native commands), the details of the
  DOSBox versions and the titles of templates and filters to the width of
  their database column (256 characters); a longer value, e.g. from an
  import, made saving fail otherwise. Taken over from DBGL 0.100 beta 18 by
  Ronald Blankendaal ("remax"). Links (2048 characters) and filter
  expressions (no limit) are not cut.
- DOSBox-X releases from 2020 to early 2024 (0.83.x, 0.84.x, 2022.08.0 to
  2023.09.01): DBGL now also recognizes the version numbers without a full
  date and offers the settings of 2024.03.01 in the profile. Before, they
  counted as 0.82.20 of 2019 (e.g. without the output "ttf" and many
  graphics cards) or as DOSBox 0.73. Checked against the reference
  configurations of the releases of 2022 and 2023.

0.101 alpha 52 (2026-11-21)
---------------------------
New
- RAWG as one more source of online info (Settings > Web Information
  Archives > RAWG), with an own free key: game data, description, rating
  and screenshots. RAWG is named as the source with a link to its page of
  the game, as it asks.
- Menu Profiles > "Import games from LaunchBox": takes over the MS-DOS
  games of an own LaunchBox collection that LaunchBox starts with DOSBox as
  profiles, with their DOSBox configuration, the data from LaunchBox, the
  cover and the manual. eXoDOS games stay with the eXoDOS import of their
  own; nothing in LaunchBox is changed. Favourite, rating, "completed",
  number of starts and play time come along.
- Profile context menu > "Add to LaunchBox" (Windows): enters the chosen
  profiles as games of the platform MS-DOS in LaunchBox, with the data of
  the profile, the manual, the cover and the screenshots. They start
  through DBGL (the play time is counted) or directly with DOSBox. Games
  that are there stay unchanged; a copy of the platform file is kept as
  MS-DOS.xml.dbgl-backup.
- ScummVM: menu Profiles > "Import ScummVM games" takes over the games in
  the scummvm.ini of ScummVM as profiles (status "ScummVM"). ScummVM is
  entered on the tab "DOSBox versions" if it is not there yet. They start
  with ScummVM instead of DOSBox; the play time is counted, and Steam,
  LaunchBox and shortcuts on the desktop start ScummVM too. The settings of
  the games stay in ScummVM; scummvm.ini is only read. The daily search for
  new DOSBox versions tells about new ScummVM versions too (DBGL reads the
  installed version from scummvm.ini). The ScummVM entry has a window of its
  own (title, folder, program, parameters; the version number comes from
  scummvm.ini by itself), ScummVM profiles a lean editor of their own (data,
  the ScummVM game from the list, scummvm.ini, links 1 to 8 with their titles
  and "Remove" as in the profile window, information; on a tab of its own the
  custom fields 1 to 14) with "Consult ..." for game data, covers and
  screenshots from a game database to choose;
  "Online info" opens it too. Screenshots taken in the game with Alt+S are
  copied into the picture folder of the profile after playing (ScummVM keeps
  its own). ScummVM cannot become the default version and does not appear
  when switching the DOSBox version or in the choice of versions of the
  profiles; the search for duplicates knows ScummVM games by their ID; the
  import list can be sorted by each column. ScummVM cannot be removed from
  the list of DOSBox versions (button and menu greyed out; the Delete key
  tells where to hide it). Settings > General > "Show the functions for
  ScummVM" hides the import, the update search and its entry in the list of
  DOSBox versions. Its small configuration file is in the folder config, not
  in the main folder.
- Menu DOSBox > "Look for sound files...": searches the whole computer or
  a folder for SoundFonts (.sf2, .sf3), MT-32 and CM-32L ROMs (known by
  their checksums), Roland Sound Canvas ROMs and Gravis Ultrasound patches
  (ULTRASND). The search can be stopped and changes nothing. What is found
  can be copied to where DOSBox Staging looks for it by itself (nothing is
  moved or overwritten); a SoundFont folder can be kept as the folder of the
  SoundFont choice.
- Menu Profiles > "Import games without a profile from folder...": finds
  the DOS games in a folder (each game in a folder of its own) that have no
  profile yet (a DOS program in it, no profile starts or mounts anything in
  it). Folders with Windows programs only and GOG/Steam games with their own
  DOSBox (they have an import of their own) are left out. The start file is
  guessed and shown in the list, a setup program is taken, a dosbox.conf in
  the game folder is used.
- One-click update (Windows, Linux): on request a Java 21 of DBGL's own
  comes along (Eclipse Temurin from Adoptium, the runtime only, about
  50 MB), or the one there is brought up to the newest Java 21. It goes into
  the folder jre of DBGL, where launch.exe and the Linux start script look
  first; the Java of the system stays as it is. The file is checked by its
  SHA-256 checksum, unpacked safely and started once before it is put in
  place; if something goes wrong, the update goes on without Java.
  The update window of this version on has the option, so it first shows
  when updating to the next one; updating from alpha 51 to this one does not
  show it yet (to have Java right away: the stand-alone package).
- The stand-alone package for Windows comes with Java 21 (Eclipse Temurin
  21.0.13.1, in the folder jre): Java no longer has to be installed first.
  launch.exe and dbgl.cmd take it first; the one-click update can keep it
  up to date. With Java 21 installed already, the second Windows package
  without Java (...-windows-without-java.zip) does. On Linux and macOS
  Java is still installed by the user.
- Profiles > "Export profiles list": a new kind "Table with columns of
  your choice" (CSV for Excel/LibreOffice, a web page or text with the
  columns lined up). Ticked at first
  are the columns of the profile list in their order; each column can be
  added, left out and moved up or down, and the last choice is kept. The
  profiles come as filtered and sorted in the list, setup and
  favourite as Yes/No.
- TV mode: a background colour and a background picture under Preferences >
  GUI options > TV mode. A light colour is made darker and the picture is
  shaded, so that the writing stays easy to read; the picture fills the
  screen without being stretched.
- Screenshots at the right, above the description (asked for on Vogons):
  Preferences > GUI options > Screenshots > Position "At the right, above
  the description". Up to four pictures stand two in a row, as wide as the
  column; the last one shows "+n" when there are more, a click enlarges
  them as before. While the description is hidden, they are below the list.
- Profile > Rendering > Shader > "Preview...": shows roughly what the chosen
  shader does to the picture (sharp, soft, scanlines, picture tube, curved,
  smoothed edges) on a built-in test picture in the style of old DOS games:

- Version detection: "Detect" button in the DOSBox version dialog. On save, the
  entered version is compared with the actual one and DBGL asks if they
  differ.
- Versions that are not listed are mapped to the nearest generation, e.g.
  Staging 0.83.x/0.84 or newer DOSBox-X versions.
- DOSBox-X version list extended up to 2026.10.01.
- More fields for DOSBox Staging 0.83: hard disk and floppy disk speed,
  cpu_idle, keyboard_capture, SoundFont folder and volume, Sound Canvas, new
  page "Image adjustments", denoiser, disk noise, options of the built-in DOS
  mouse driver.
- New menu "Switch profiles to another DOSBox version": switches all profiles
  of one DOSBox version, with a preview and a report that can be saved.
- Status window: copy the output and save it as a text file.
- All new texts in 20 languages.


0.101 alpha 0 (2026-10-31)
--------------------------
- Support for DOSBox Staging 0.83.0:
  - Renamed settings, e.g. windowresolution -> window_size,
    fullresolution -> fullscreen_mode, glshader -> shader,
    share -> file_locking.
  - Removed settings and switches in on/off notation.
  - Automatic conversion when switching from and to 0.83.
  - New fields: CRT color profile, deinterlacing, dedithering, image
    adjustments, Sound Canvas model and ROM folder, denoiser, hard disk and
    floppy disk noise, SID filter, built-in DOS mouse driver.
  - Creating the DOSBox configuration adapted for 0.83.
- Fixed: profiles contained empty entries like "locale_period=" or
  "file_locking=". Empty values that would override a DOSBox default are now
  left out.
- Status window: DOSBox Staging 0.83 no longer opens a console on Windows.
  DBGL now shows the DOSBox output itself, unless "Hide DOSBox Status Window" is
  turned on.
- Version number 0.101 (now 0.101 alpha 0).


Notes
-----
- DOSBox SVN, ECE and Daum are only tested with sample texts, not with real
  executables and configurations.
- PC-98 HDI support is tested with one real image (Windows 95 for PC-98):

  emulation of DOSBox-X.
